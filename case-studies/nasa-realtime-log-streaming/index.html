Case study / Cloud data engineering

NASA real-time log streaming.

The brief

Turn a static HTTP access-log dataset into a continuous, observable analytics system with low latency and no server management.

  • Python
  • Cloud Pub/Sub
  • Dataflow
  • Apache Beam
  • BigQuery
  • Looker Studio

Executive summary

From raw events to live decisions.

This project implements an end-to-end, serverless ingestion and analytics pipeline on Google Cloud Platform. NASA HTTP access logs are parsed into structured events, buffered for resilient delivery, transformed as a live stream, stored in an analytical warehouse, and exposed through an interactive dashboard.

Latency target
Sub-second
Delivery model
At least once
Operations
Serverless

Architecture / Event-driven flow

Five decoupled stages.

Each service has one responsibility, allowing ingestion, processing, storage, and reporting to scale independently while Pub/Sub absorbs changes in traffic volume.

  1. Stage 01

    Producer

    Python

    Parses NASA HTTP logs, normalizes timestamps, and publishes structured JSON events.

    ->

  2. Stage 02

    Ingestion

    Cloud Pub/Sub

    Buffers traffic, persists messages, and decouples producers from downstream processing.

    ->

  3. Stage 03

    Processing

    Dataflow

    Runs Apache Beam transformations, validates the schema, and scales workers with demand.

    ->

  4. Stage 04

    Warehouse

    BigQuery

    Accepts streaming inserts and provides partitioned, serverless analytical storage.

    ->

  5. Stage 05

    Visualization

    Looker Studio

    Surfaces throughput, status-code distribution, and frequently requested endpoints.

Component breakdown

What each layer owns.

Clear service boundaries reduce coupling and make failures easier to isolate, retry, and monitor.

Layer 01

Traffic producer

Python application

  • #Reads raw Common Log Format events from the NASA access log dataset.
  • #Parses unformatted lines into structured JSON payloads.
  • #Normalizes timestamps to ISO 8601 UTC before asynchronous publishing.

Layer 02

Ingestion layer

Cloud Pub/Sub

  • #Acts as a serverless event bus and traffic shock absorber.
  • #Decouples log generation from the processing engine.
  • #Provides message persistence and at-least-once delivery during traffic spikes.

Layer 03

Stream processor

Dataflow / Apache Beam

  • #Runs the managed PubSub_Subscription_to_BigQuery streaming pipeline.
  • #Scales worker instances dynamically in response to throughput.
  • #Validates schemas, casts types, and transforms events without disk-backed staging.

Layer 04

Analytics storage

BigQuery

  • #Serves as the centralized, serverless data warehouse.
  • #Uses streaming buffer insertions to make rows available in near real time.
  • #Supports efficient aggregation through a structured analytical schema.

Layer 05

Visualization layer

Looker Studio

  • #Connects directly to BigQuery with short data-freshness intervals.
  • #Tracks overall throughput and HTTP response-code distributions.
  • #Ranks the most frequently visited NASA resources and endpoints.

Target table / http_requests

A schema built for streaming analysis.

Structured fields replace raw log strings so analysts can group requests, rank endpoints, and aggregate transferred bytes without parsing at query time.

CREATE TABLE `log-service-simulation.nasa_logs.http_requests` (
  host STRING,
  timestamp TIMESTAMP,
  request_method STRING,
  endpoint STRING,
  protocol STRING,
  status_code INTEGER,
  bytes_sent INTEGER
);

Implementation journey

Production constraints changed the design.

Challenge 01 / Capacity

Zone resource pool exhausted.

Initial Dataflow deployments failed with ZONE_RESOURCE_POOL_EXHAUSTED when the worker pool could not initialize in us-central1-c.

Resolution

Worker allocation was rerouted explicitly to us-central1-a with the Dataflow job's zone configuration.

Challenge 02 / Data quality

Timestamp precision broke inserts.

BigQuery template validation dropped messages containing fractional microseconds such as .221034Z.

Resolution

The producer now formats every timestamp with strftime('%Y-%m-%dT%H:%M:%SZ'), aligning events with the expected ISO 8601 format.

Analysis / Verification

Queries that prove the stream.

Traffic and status distribution

Aggregates request volume and transferred bytes for each HTTP method and response status.

SELECT
  request_method,
  status_code,
  COUNT(*) AS total_requests,
  SUM(bytes_sent) AS total_bytes
FROM `log-service-simulation.nasa_logs.http_requests`
GROUP BY request_method, status_code
ORDER BY total_requests DESC;

Top requested resources

Ranks endpoints by request count while measuring their total network payload.

SELECT
  endpoint,
  COUNT(*) AS request_count,
  SUM(bytes_sent) AS total_bytes
FROM `log-service-simulation.nasa_logs.http_requests`
GROUP BY endpoint
ORDER BY request_count DESC
LIMIT 10;

Results / Takeaways

High-throughput streaming

Low operational overhead

Managed GCP services handled buffering, compute scaling, storage, and reporting without manually maintained servers.

System-design proof

The implementation connects event-driven architecture concepts to a working cloud pipeline with observable data and recoverable delivery boundaries.
